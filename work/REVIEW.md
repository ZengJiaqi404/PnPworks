## 4. 关键技术发现（本次最重要的一条）

**模型的 4 个关键点约束的是「两根灯条围成的矩形」，不是整块装甲板的外框。**

| 证据 | 数值 |
|---|---|
| 实机关键点像素跨度 | 619.5 × 147.1 px，比例 **4.211** |
| 假设「灯条矩形 224×54」 | 比例 4.148（偏差 1.5%）→ PnP 成功，Z=0.868 m，重投影 1.67 px |
| 假设「整板 224×126」 | 比例 1.778（差 2.4 倍）→ PnP **失败**（重投影超限） |

因此 `--armor-w/--armor-h` 的物理含义必须是 **灯条外沿间距 / 灯条长度**。
这条结论决定了后面所有距离数据是否可用，也是排查「为什么一直检不出」时最先要验证的量。

## 5. 实验与量化指标

| 实验 | 条件 | 结果 |
|---|---|---|
| 标定精度（实测） | 2093 帧录像 → 40 帧抽样 → 剔除 2 个异常 | RMS **0.749 px**，逐图中位 0.656，最大 0.896 |
| 内参一致性 | 同一次标定 | fx/fy 差 **0.05%**；主点 (713.6, 518.6) vs 中心 (720, 540) |

| 关键点跨度标定 | 90 cm 实机，蓝灯板 | 推出 224×54，PnP Z=0.868 m（卷尺 0.9 m，−3.6%） |
| 实机近距离 | 卷尺 0.70 m | 中位 **0.649 m**，std **±3.5 mm**，偏差 −7.2%，262 帧有效 |

## 6. 已知问题与风险

| # | 问题 | 严重度 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | 距离系统性偏低 7%～15% | **高** | 绝对距离偏小，越远偏得越多 | 做 1.000 m 标定实验反解有效跨度：`armor_w' = 224 × 读数 / 1.000`；同时确认卷尺基准点（镜头前端面到板面）与板面正对 |
| 2 | 标定 RMS 0.749 px（目标 <0.5） | 中 | 远距角点噪声放大（±26.7 mm） | 重录：更慢移动、更强照明、覆盖四角、≥40 样本、板面平整 |
| 3 | 平面 PnP 翻转二义性 | 中 | 极小/极远目标偶发跳变 | 已用「双解 + 重投影误差 + 连续性」缓解；可再加时序评分 |
| 4 | 角点排序在大滚转角（>45°）失效 | 中 | 板子侧翻时顺序错、位姿发散 | 对两套排序各解一次 PnP 取误差小者，或按灯条方向聚类 |
| 5 | 单目标假设（取最高置信度） | 中 | 多机器人只跟一个 | 扩展为多实例 KF + 类别/距离关联 |
| 6 | 70 cm 档仅 262/450 帧有效 | 低 | 数据段短，非算法问题 | 录制时板子保持在画面内；或用 `--csv` 只取有效段统计 |
| 7 | 无 CI / 单元测试框架 | 低 | 回归靠人工跑 `selftest` | 接 pytest + GitHub Actions（可跳过权重相关用例） |
| 8 | 权重与大视频不入库 | 低 | 克隆后需自备 | README 已说明；可用 Release 附件或 Git LFS |
| 9 | 未加 LICENSE | 低 | 权属不明 | 按团队要求补 MIT 或私有声明 |
| 10 | 滚动快门/运动模糊未建模 | 低 | 高速运动时角点偏移 | 短曝光 + 补光已显著缓解 |

## 7. 代码质量走查

**做得好的地方**

- 关键坑有注释固化：`kf.py` 解释「为什么不能多调一次 predict」；`armor.py` 解释翻转二义性与择优；`calibrate.py` 解释 `fast` 模式用途。
- 数值兜底完整：`z<=0` 丢弃、重投影 >6 px 丢弃、跳变超门限重置、退化四边形过滤、低帧率告警。
- 资源管理：相机 Stop/Close/Destroy、VideoWriter release、**采集线程 join**（修复了退出时 C++ 线程析构导致的 core dump）。
- 调试友好：`focus.py` 用 Laplacian 方差量化对焦，`record.py` 一键录原始画面，`selftest.py` 无相机自证数学。
- 路径可移植：`PYTHON` 环境变量、`weights/best.pt` 候选、`ARMOR_WEIGHTS`。

**可以更好的地方**

- `pipeline.py` 428 行偏长，绘制/录制/导出可拆分为 `render.py`、`recorder.py`。
- 20+ 命令行参数建议下沉到 `config.yaml`。
- CSV 缺 `reproj_px`、`yaw/pitch/roll` 字段，事后精度分析不便。
- `find_corners(fast=...)` 建议改成枚举或拆成两个函数。

## 9. 环境与复现

```bash
./run.sh --tool selftest                    # 数学自检（无需相机）
./run.sh --tool focus --exposure 12000      # 对焦辅助
./run.sh --tool record --seconds 40         # 录棋盘格视频
./run.sh --tool calibrate --video assets/chessboard.mp4 --cols 9 --rows 6 --square 26
./run.sh --exposure 9000 --gain 18          # 实时六步
./run.sh --tool compare                     # 两距离档对比图
./run.sh --tool plot --synthetic            # 滤波效果对比图（有真值）
```

约束：MVS 设备节点在容器/沙箱内不可见，必须在桌面会话直接运行；相机独占，MVS 客户端与程序不能同时采集。

## 10. 结论与建议下一步

六步链路已在真实相机上闭环，误差量级明确：**近距离重复性 3.5 mm、远距离 26.7 mm**，滤波把仿真 RMSE 降低 42%。

提交前建议只做两件事，投入产出最高：

1. **1.000 m 标定实验**反解有效跨度，把 −7%～−15% 的系统偏差压到 2% 以内；
2. **重录一段高质量标定视频**（更亮、更慢、覆盖四角、≥40 样本），把 RMS 从 0.749 压到 0.5 以下。

其余问题（多目标、大滚转、CI）属于扩展项，不影响本次作业验收。
